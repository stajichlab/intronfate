# Testing

```sh
cargo test --workspace                      # Rust: unit, integration, CLI end-to-end, doc tests
cargo clippy --workspace --all-targets      # must stay warning-free
cargo fmt --check
python3 -I scripts/test_malin_to_matrix.py  # the Python converter's fixture tests
python3 -I scripts/test_howto_scripts.py    # the HOWTO helper scripts' fixture tests
python3 -I scripts/test_doc_samples.py      # the prose pages still match the binary (needs a built binary)
python3 -I scripts/mutate_doc_samples.py    # proof that those checks fail when a page is wrong (needs a built binary)
```

This page is the one place that lists the test layers; other pages link here rather than quoting test counts. `cargo test --workspace`
runs everything except the two tests marked `#[ignore]`: the real-data likelihood convergence check and the MALIN `*.rates` comparison
(both below, both needing files from outside the repository). The CLI end-to-end tests are the slow part
(about two minutes in a release build, longer in a debug build). Nothing in the repository runs these checks automatically (there
is no CI workflow), so they are the pre-merge gate by convention: `cargo build --release && cargo test --workspace && cargo clippy
--workspace --all-targets && cargo fmt --check` plus the three Python scripts above.

## Layers

| Layer | Where | What it proves |
|---|---|---|
| Unit | `crates/intronfate-core/src/*.rs` (`#[cfg(test)]`) | Coordinate model, GFF parsing, CDS merging on both strands, 5'-partial CDS, frame/phase checks, Newick, bitsets, MALIN parsing. |
| Brute-force | `score.rs` tests | Dollo DP and Fitch/Hartigan are compared with exhaustive search over every `{present, absent, missing}` tip pattern on eight tree shapes, polytomies included. Reconstructions must realise exactly the reported step count. |
| Pipeline integration | `crates/intronfate-core/tests/per_cell_missing.rs` | Join → project → matrix → file → score on tiny hand-built families: a gap scores `?` and no loss, the same taxon aligned through scores one loss, `?` survives `matrix.tsv`, adding an all-missing taxon changes no score, trimmed alignment rows are rejected. |
| Combined matrix | `crates/intronfate-core/tests/combined.rs` | A combined matrix scores exactly the sum of its families (totals and every branch), keeps the same column in two families as two sites, never pairs sites across families, keeps missing taxa `?`, survives the file round trip, and refuses duplicate names, mixed flank/phase mode and already-combined inputs. |
| CLI end to end | `crates/intronfate-cli/tests/cli.rs` | The real binary: golden output for every example, hand-calculated values, `matrix`+`score` = `analyze`, gzip input, exit codes, error messages, output-folder collisions, and the list and folder input forms (`--msa-dir`/`--msa-list` give byte-identical results to repeated `--msa`; `--gff-dir`/`--proteins-list`; `score --matrix-dir`, `convert --matrix-dir/--matrix-list`, a `combined` sub-folder skipped). `inputs.rs` unit tests cover the extension rule, list parsing and folder scanning. |
| Examples | `examples/*/` | Each has `run.sh` and a committed `expected/`; the CLI test re-runs them and requires byte-identical output. Their READMEs list the hand-checked numbers. |
| Randomised vs reference | `matrix.rs`, `annotation.rs`, `tree.rs`, `score.rs` tests | Random CDS layouts on both strands (with 5'-partial skips and exon rows) against a naive per-base model; random matrices through `matrix.tsv` and MALIN; random trees for `mrca`, Dollo and Fitch against brute force; weighted Dollo against brute force with missing tips; the parallel pairwise code against the per-pair reference; the `ambiguous` flag against an exhaustive count of optimal labellings. |
| Cross-implementation | `scripts/test_malin_to_matrix.py` vs `malin.rs` tests | Two independent MALIN importers agree on the same fixture (`tests/data/malin_tiny.table`). |
| Likelihood | `likelihood.rs` tests, `cli.rs::likelihood_writes_its_tables_and_reads_error_rates` | Likelihood, ascertainment term, node and pair posteriors equal brute-force enumeration (errors, `?`, polytomy, unscored tip); conditional probabilities of all seen patterns sum to 1; EM never decreases the likelihood; simulation recovery of losses, and of terminal losses only when misses are modelled; the larger root branch stays fixed; family-block bootstrap; CLI tables, error-file forms and refusals. MALIN's global never-seen correction (`--ml-never-seen global`): log-likelihood and expected never-seen positions against brute force, equal to the per-pattern form without missing cells, EM monotone and stationary with 15 % missing cells; CLI summary line. Free levels (SPEC §5.5d): brute-force class mixtures with unequal class probabilities, recovery of a slow level's probability and multiplier, stationarity, option checks, the `.rates` level reader, CLI summary lines; the MALIN comparison itself is an ignored test (`tests/malin_rates.rs`, run on the HPCC with MALIN's licensed files, `bench/L1_malin_likelihood`). Separate gain and loss classes (SPEC §5.5c): every class's transition matrix against the closed form of a two-state chain, the class grid, brute-force class mixtures for loss-only, gain-only and 2×3 grids, simulated recovery of the loss shape and better fit than shared classes, option checks; CLI columns and refusals. `--ml-max-iter` is an exact limit (`max_iter_is_an_exact_limit_on_e_steps`). Origins (SPEC §5.6, `--ml-origins`): posterior probabilities of none, one and two or more origins and the likelihood ratio against enumeration of every state assignment with origins counted directly (no classes, and a three-class mixture); CLI columns sum to 1; on simulated data with known origins (12 tips, 6,000 positions, 540 convergent) the model is fitted without the truth and the evidence is scored against it: AUC 0.83, at ln LR > 2 2.3 % of single-origin and 32 % of convergent positions are flagged, positions with a posterior above one half are mostly convergent (`origin_evidence_separates_convergent_from_single_origin_positions_in_simulated_data`). Soft cell evidence (SPEC §5.6b, `--ml-soft-evidence`): the raw column probability with two soft cells equals the mixture of the four hard-cell probabilities (the full conditional likelihood is covered in the Soft evidence row), the likelihood lies between the two hard versions, EM converges; unknown site or taxon and out-of-range probabilities are refused; CLI run and refusals (`likelihood_takes_soft_evidence_from_a_table`). Scripts of the measurements below: `bench/test_flank_scripts.py` (hand-derived gap positions; it reads the matrix `column` as 0-based, so the off-by-one that first gave wrong F1/F2 numbers fails it). Measurements, not tests: [F1](../bench/F1_flank_tuning/README.md) (`--flank`) and [F2](../bench/F2_column_ambiguity/README.md) (missing cells behind short gaps). Rate classes (SPEC §5.5b): incomplete gamma and Yang's (1994) category rates, continuous-time composition of class transitions, class mixture and posteriors against brute force, simulated shape recovery, stationarity in α and branches, homogeneous data → large α, option refusals; CLI `--ml-rate-categories` / `--ml-gamma-shape`. |
| Likelihood, real data | `crates/intronfate-core/tests/ml_realdata.rs` (`#[ignore]`) | The EM fit reaches the same optimum from several starting points and with a far stricter tolerance, with no error and with a uniform error, on a real matrix. Needs a matrix and tree from outside the repo, so it runs only on request: `INTRONFATE_ML_MATRIX=matrix.tsv INTRONFATE_ML_TREE=tree.nwk cargo test --release -p intronfate-core --test ml_realdata -- --ignored --nocapture` (instructions at the top of the file). |
| MALIN agreement | `crates/intronfate-core/tests/malin_rates.rs` (`#[ignore]`) | This tool's fit against MALIN's own printed rate estimates on MALIN's published tables (run: `bench/L1_malin_likelihood`). Needs MALIN's licensed files, which are git-ignored, so it runs only where you have them: `INTRONFATE_MALIN_TABLE=<dir>/rogozin_introns_table INTRONFATE_MALIN_RATES=<dir>/Rog-ecdysozoa.rates cargo test --release -p intronfate-core --test malin_rates -- --ignored --nocapture` (options at the top of the file). |
| Standard input | `util.rs` tests, `cli.rs::standard_input_*` | A stream is read whole, plain, gzipped, as two gzip members, empty, and with a stray `0x1f`; standard input can be claimed once; each of the GFF, proteins, tree (plain and gzipped), the alignment (renamed `stdin`) and `score --matrix` read from a pipe gives the same files as the file route; two inputs as `-` (also in one repeated option) are refused with a message that says so; empty input fails instead of hanging. |
| Standard output | `outmode.rs` tests, `cli.rs::stdout_*`, `convert_to_malin_*`, `a_reader_that_closes_early_*` | `--stdout` for project, matrix, analyze and score prints exactly the bytes of the file that `-o DIR` writes (the `matrix` path line of `summary_score.tsv` masked), and with `-o` the directory is complete too; `--stdout` alone leaves the working directory empty and summary lines off stdout; unknown names, several alignments, `--combine`, a table the options did not write, and `demo`/`convert` are refused early with nothing printed; `convert --to-malin -o -` equals the file route and `--from-malin -o -` is refused; a reader that closes at once gives exit 0 and an empty stderr. |
| Soft evidence | `likelihood.rs::soft_*`, `a_fit_with_soft_carriers_*` | The conditional likelihood and the origin posteriors of columns with soft cells match a brute-force enumeration of the configurations in which the position was seen (error rates, missing cells, ordinary and soft carriers); ln L is at most 0 and continuous as `q` approaches 1; the raw mixture of two soft cells is the four-term sum of hard cells; a simulated fit with positions that have only soft carriers converges, has ln L below 0, is a stationary point of the likelihood and beats the parameters fitted to the ordinary version of the data. Turning the seen-conditioning off fails the brute-force, origin and fit tests (the bug found on the V6 families, J1). |
| Junction support | `junctions.rs` tests, `cli.rs::junctions_*` | The map is `p0` at no reads, halves the doubt at `k` reads, rises monotonically and never falls below `p0`; STAR and BED parse with their own coordinates and strands (BED start shifted by one, an undefined strand counts for either, a wrong strand or a one-base shift is no support); the best-supported of several introns behind a cell wins; a CLI run on the quickstart gives 0.96 for 12 reads and 0.8 for none, leaves taxa without a table hard, feeds `--ml-soft-evidence` and moves the likelihood, writes the same bytes to `-o -`; bad `TAXON=FILE` and format are refused; a table on other sequence names is an error, one-base-shifted coordinates and under-1% support warn (30 introns); a cell the matrix masked (`?`) is never softened (core and CLI); `--combined-labels` over several alignments feeds `score` on the combined matrix; `sites.tsv` labels equal the matrix labels under `--ignore-phase` (fails on the old label). `bench/test_junction_scripts.py` checks the BAM-to-junction script and, with a built binary, that a read over the annotated intron is exact support (a one-base-short read is not), so the coordinate convention is pinned end to end. |
| Compressed input | `util.rs::read_text_*`, `cli.rs::every_table_and_list_input_reads_gzip_like_plain_text` | `read_text` undoes gzip whatever the file is called; a gzip `matrix.tsv`, list file, MALIN table, junction table, `introns.tsv` and `sites.tsv` give the same results as the plain files. The test fails on the old `read_text`. |
| MALIN FASTA input | `malin_fasta.rs` tests, `cli.rs::malin_fasta_*` | Headers parse with the tags in either order, empty `{i i}`, spaces after commas, CRLF and repeated positions; no organism, no intron tag, position 0, a non-number, an unclosed tag and a header that starts with a tag are refused with the row named; a MALIN FASTA written from the quickstart gives the same `matrix.tsv`, `presence.tsv`, `pairwise.tsv` and `counts_sites.tsv` as the GFF route; organisms become the taxon names and feed `analyze` against a renamed tree; standard input works; two rows of one organism and `--gff` together with `--malin-fasta` are refused. Not yet compared with a MALIN run on the same files. |
| How-to helpers | `scripts/test_howto_scripts.py` | `one_protein_per_gene.py` keeps the longest isoform per gene for NCBI- and Ensembl-style GFF3 (ties, CDS under a gene, internal stops, missing proteins); `make_families.py` builds the tiers from a tiny OrthoFinder layout with plain and gzip proteomes; `doc_blocks.py` extracts only ```` ```sh ```` blocks and refuses a `--sub` line it cannot find. |
| How-to, end to end | `bench/D1_howto_public_genomes/run_howto.sbatch` (HPCC) | `docs/HOWTO.md` run as written, on both examples, from download to `dollo_branches.tsv`. |
| Docs vs the binary | `scripts/test_doc_samples.py` | The pages still describe the tool: README's `demo` sample equals what `demo` prints, row by row (the stale `ambiguous` column, the dropped `# format=2` and self-check lines); every flag in `--help` is named on a page and every flag the USAGE §4 table claims exists; every file an all-methods run writes and every `summary_score.tsv` key has an OUTPUTS.md row; every code a messy run puts in `diagnostics.tsv` / `unmatched.tsv` has a §8 row. Skipped without a built binary; each fixture asserts its own breadth (which codes it reaches, how many files and keys it collected), so a check cannot pass by quietly testing nothing. |
| The checks on the docs, checked | `scripts/mutate_doc_samples.py` | A green `test_doc_samples.py` only shows the page and the tool agree, not that the comparison would notice when they don't — the same weakness golden files have. So break one documented fact at a time in a throwaway copy of the tree (the pre-fix `ambiguous yes` in README's `demo` table, the dropped `# format=2` header and self-check lines, a deleted OUTPUTS row for a file the tool writes, a renamed `summary_score.tsv` key, a deleted §8 row, a mangled option name, a §4 row for a flag that has never existed) and require the intended check to fail, and that the unmutated copy passes. 8 mutations, exit 0 only when every one is attributed correctly. Verified from the other side too: delete the README row comparison from `test_doc_samples.py` and the harness reports `MISSED` and exits 1. Unlike `test_doc_samples.py` it **errors rather than skips** when there is no binary — a proof run with nothing proved must not look like a pass, so build before running it. |

Golden files only catch *changes*. The numbers that make the examples trustworthy are the
hand-calculated ones (`quickstart_numbers_match_the_hand_calculation` and the example READMEs).

## Test-suite review (2026-11-11)

An Opus agent applied 44 single-line mutations one at a time to a copy of the repo and ran the suite on each.
Surviving mutants became tests: a hand-written truth table for `cell_observable` (every phase × flank × gap
position, plus the merged `--ignore-phase` window), weighted Dollo against brute force, the clamp boundary,
`read_tsv`/MALIN duplicate-row merging, `write_atomic` leaving no temp file, counts with unannotated taxa, and
thread-count independence of the output. It also found two real bugs: the `ambiguous` flag in `mp_sites.tsv`
was true for every unrooted-ish case, and an empty matrix exported to an unreadable MALIN table. Both are fixed.
Golden files are only regression tests (they were generated by the code); the independent evidence is the
hand-calculated values and the randomised reference tests above.

## Adding a case

- New parsing behaviour: a unit test next to the code with the smallest failing input.
- New science (a scoring rule, observability rule): a hand-built family in
  `per_cell_missing.rs`, and if it is a DP, extend the brute-force check.
- New example: copy an `examples/` folder, keep `run.sh` self-contained (`INTRONFATE` env var,
  relative output dir `out`), generate `expected/` with `./run.sh out && rm -rf expected && mv out expected`,
  **check the numbers by hand**, add the name to the list in `every_example_reproduces_its_expected_output_exactly`.

## What is not tested here

Real-genome behaviour and speed. Per project policy analyses and benchmarks run on the HPCC; they are indexed in
[`bench/README.md`](../bench/README.md) (performance: V3; validation against MALIN: V1; the how-to run end to end: D1).
The third-party MALIN datasets in `Malin/` are git-ignored and are not used by the automated suite.
